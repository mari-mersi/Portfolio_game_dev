# Архитектура проекта Portfolio_game_dev 

## 1. Общие принципы (важно прочитать до кода)

1. **Один проект, слоистая папка-архитектура** — вместо отдельных .csproj используем папки `Data/`, `Services/`, `Models/`, `ViewModels/`, `Controllers/`, `Areas/Admin/`. Разделение по ответственности сохраняется, но без сборок.
2. **Никаких репозиториев (Repository/UnitOfWork)** — EF Core `DbContext` уже является Unit of Work. Для одиночного проекта это лишний слой.
3. **Сервисы — только там, где есть логика.** Если действие — «взять из БД и отдать», можно вызывать `DbContext` прямо из контроллера. Сервис оправдан, когда есть Markdown-рендер, PDF, валидация, кэш, mock-режим.
4. **Mock-сервисы — только на время разработки без БД.** Потом убираются. Не тащи их в прод-архитектуру «на всякий случай».
5. **Admin CRUD — без CQRS, MediatR, AutoMapper.** Ручной маппинг во ViewModel. Для 6 сущностей это 10 минут кода и ноль магии.
6. **Сначала вертикальный срез, потом глубина.** Сделай Home → Projects → Skills → Resume (MVP), потом Blog/Experience/Admin.

## 3. Модели (Models) — уточнения

Добавь к своим сущностям базовые вещи, которые почти всегда забывают и потом переделывают:

```csharp
public abstract class BaseEntity
{
    public int Id { get; set; }
    public DateTime CreatedAt { get; set; } = DateTime.UtcNow;
    public DateTime? UpdatedAt { get; set; }
}
```

**По каждой сущности — минимум:**

| Сущность | Ключевые поля | Связи |
|---|---|---|
| `Project` | `Title`, `Slug` (uniq), `ShortDescription`, `DescriptionMd`, `CoverImage`, `RepoUrl`, `DemoUrl`, `IsPublished`, `SortOrder` | `ProjectMedia[]`, `Tag[]` (M2M) |
| `ProjectMedia` | `Url`, `Type` (Image/Video), `SortOrder` | `Project` |
| `Skill` | `Name`, `Category` (enum/строка), `Level` (1-5), `Icon`, `IsFeatured` | — |
| `Experience` | `Company`, `Role`, `StartDate`, `EndDate?`, `DescriptionMd`, `IsCurrent` | — |
| `BlogPost` | `Title`, `Slug`, `ContentMd`, `CoverImage`, `PublishedAt`, `IsPublished`, `Tags` | `Tag[]` |
| `Tag` | `Name`, `Slug` | `Project[]`, `BlogPost[]` |
| `ContactMessage` | `Name`, `Email`, `Message`, `CreatedAt`, `IsRead`, `IpHash` | — |

**Обязательно:**
- `Slug` для `Project` и `BlogPost` (используешь `DetailsBySlug`, `Post(slug)` — уже в контроллерах).
- Индекс на `Slug` (uniq) и на `IsPublished + PublishedAt`.
- `IsPublished` — чтобы писать черновики.

## 4. ViewModels — правки

Ты перечислил `*ViewModel`, это правильно. Добавь:

**Shared:**
- `PagedResult<T>` — `Items`, `Page`, `PageSize`, `TotalCount`, `TotalPages`. Используется в `Blog/Index`, `Projects/Index`.
- `HomeViewModel` — собери одним запросом: `FeaturedProjects`, `FeaturedSkills`, `LatestPosts`, `Hero`.

**Admin:**
- `DashboardViewModel` — счётчики (`ProjectsCount`, `SkillsCount`, `UnreadMessages`, `PostsCount`).
- `ProjectEditViewModel` — с `IFormFile CoverImage`, `List<int> SelectedTagIds`.
- `ContactMessageListViewModel` — на будущее (админ смотрит сообщения).

> **Правило:** ViewModel не должна содержать entity напрямую, если ты рендеришь форму с валидацией. Иначе EF начнёт трекать лишнее.

## 7. Валидация

Ты указал `FluentValidation` — ок, но для одиночного проекта **Data Annotations + IValidatableObject** часто быстрее. Компромисс:

- **Data Annotations** — на всех ViewModel (быстро, встроено, работает с клиентской валидацией).
- **FluentValidation** — только для `SkillEditViewModel` и `ContactViewModel` (если там специфичные правила, например антиспам).

Не тащи FluentValidation на все 10 ViewModel — это 10 файлов boilerplate.

## 8. Кэширование — практично

- **Output Caching** на публичных GET-страницах: `Home/Index`, `Projects/Index`, `Skills/Index`, `Blog/Index`. Политика `"PublicPages"` — 60 сек.
- **Инвалидация** — не заморачивайся на тегах. При сохранении в админке вызывай `IOutputCacheStore.EvictByTagAsync("public")`. Всё.
- **Не кэшируй** админку и `Details` с уникальными slug — профита мало, багов много.

## 9. Безопасность и «взрослые» мелочи

- **reCAPTCHA v3** на Contact (невидимая) — 30 минут работы.
- **Rate limiting** (`AddRateLimiter`) на `/Contact` и `/Account/Login` — 10 строк в `Program.cs`.
- **AntiForgeryToken** — Razor его ставит сам, но проверь, что форма Contact не отключена.
- **HTTPS redirection + HSTS** — включи в `Program.cs`.
- **Serilog** — пиши в файл + консоль. В БД не надо.
- **Health checks** — `/health` для будущего деплоя. 3 строки.

## 10. Program.cs — каркас (без воды)

```csharp
var builder = WebApplication.CreateBuilder(args);

builder.Host.UseSerilog((ctx, lc) => lc
    .ReadFrom.Configuration(ctx.Configuration)
    .WriteTo.Console()
    .WriteTo.File("logs/app-.log", rollingInterval: RollingInterval.Day));

builder.Services.AddDbContext<AppDbContext>(o =>
    o.UseSqlite(builder.Configuration.GetConnectionString("Default")));
    // или UseNpgsql — реши заранее, миграции разные

builder.Services.AddIdentity<IdentityUser, IdentityRole>(o => {
        o.User.RequireUniqueEmail = true;
        o.SignIn.RequireConfirmedAccount = false;
    })
    .AddEntityFrameworkStores<AppDbContext>()
    .AddDefaultTokenProviders();

builder.Services.ConfigureApplicationCookie(o => {
    o.LoginPath = "/Admin/Account/Login";
    o.AccessDeniedPath = "/Admin/Account/Login";
});

builder.Services.AddControllersWithViews();
builder.Services.AddOutputCache(o => o.AddPolicy("public", b =>
    b.Expire(TimeSpan.FromSeconds(60)).Tag("public")));
builder.Services.AddResponseCompression();
builder.Services.AddRateLimiter(/* ... */);

builder.Services.AddAppServices();          // твой extension
builder.Services.AddScoped<IPdfResumeService, PdfResumeService>();

var app = builder.Build();

// pipeline
app.UseHsts();
app.UseHttpsRedirection();
app.UseStaticFiles();
app.UseRouting();
app.UseRateLimiter();
app.UseAuthentication();
app.UseAuthorization();
app.UseOutputCache();

app.MapControllerRoute("areas", "{area:exists}/{controller=Dashboard}/{action=Index}/{id?}");
app.MapControllerRoute("default", "{controller=Home}/{action=Index}/{id?}");
app.MapHealthChecks("/health");

// seed
using (var scope = app.Services.CreateScope())
    await DbSeeder.SeedAsync(scope.ServiceProvider);

app.Run();
```

## 12. Что НЕ делать (антипаттерны для твоего кейса)

- ❌ MediatR, CQRS, DDD-агрегаты, Value Objects — overkill.
- ❌ AutoMapper — маппинг в 6 местах пишется руками за 20 минут.
- ❌ Отдельные проекты `Domain`/`Infrastructure`/`Application` — ты сам этого не хочешь.
- ❌ Repository поверх EF — дублирование.
- ❌ 4 mock-сервиса — один флаг `UseMockData`.
- ❌ SignalR, gRPC, GraphQL, фоновые воркеры, очереди.
- ❌ Своя система ролей — хватит одного `Admin`.
- ❌ Юнит-тесты на всё — сделай 5–10 тестов на `SlugService`, `PdfResumeService`, `MarkdownRenderer`. Остальное проверяй руками.

## 14. Итоговая «улучшенная» карта слоёв

```
HTTP → Controllers (тонкие) 
     → ViewModels (валидация + форма)
     → Services (бизнес-логика: markdown, pdf, image, slug, contact)
     → AppDbContext (EF Core)
     → SQLite/PostgreSQL
```

Плюс сквозные: Serilog, OutputCache, RateLimiter, HealthChecks, Identity, FluentValidation (точечно), ImageSharp, QuestPDF, Markdig, reCAPTCHA.
